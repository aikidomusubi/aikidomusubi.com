{%- comment -%} WHICH PANEL SHOWS, generated from the same list that renders the panels. This rule used to be three hand-written selectors in styles/venues.less, one per venue id. A fourth venue was added to _data/venues.yml and its panel stayed `display: none` for ever: the chip appeared, the chip could be selected, and nothing happened. CSS cannot derive a selector from data, so the selector is emitted beside the data instead. It comes after the stylesheet, so at equal specificity it wins. A browser with no `:has()` drops the whole rule as unparseable and falls back to the `@supports not selector(:has(*))` block in venues.less, which shows every panel — long rather than wrong. {%- endcomment -%} {%- for v in V.venues -%}
