{%- comment -%} Dated calendar: seminars, exams, closures and changes to the regular week. Rendered at build time from _data/calendar.yml, like the weekly timetable — static HTML, indexable, no library, no fetch. Two views over one set of entries. The month grid is the default because courses here are published one to three months out, so a month usually has something in it; the list is better on a phone and better for scanning what is next. Both are in the markup and the toggle only changes which is shown, so a crawler and a reader with no JavaScript get everything either way. Every month that has entries is rendered, past ones included — the archive of who taught and when is worth keeping and worth indexing. Navigation moves between the rendered months rather than generating empty ones. Date arithmetic in Liquid, which has no date maths to speak of, is done through Unix timestamps: the first of the next month minus a day is the last day of this one. Weekday indices come from strftime %w, shifted so the week starts on Monday like the rest of the site. {%- endcomment -%} {%- assign C = site.data.calendar -%} {%- assign S = site.data.schedule -%} {%- assign L = page.lang | default: 'es' -%} {%- comment -%} Two sources, one calendar. * site.events — seminars, masterclasses and collaborations. They already exist as pages with posters and descriptions, so the calendar reads them rather than asking for the same facts twice. Adding a seminar to _events/ puts it on both pages. * C.entries — gradings, closures, cancellations and schedule changes. Dated facts with no page behind them, authored in _data/calendar.yml. Both are normalised to the same field names at the point of use. The events collection uses date_from/date_to and per-language titles; date_to is the string "blank" on single-day entries, which is why it is tested for rather than trusted. {%- endcomment -%} {%- assign entries = C.entries | sort: 'date' -%} {%- assign coll = site.events | sort: 'date_from' -%} {%- comment -%} Where an event's anchor link points, per language. {%- endcomment -%} {%- if L == 'ca' -%}{%- assign seminars_url = '/ca/seminaris/' -%} {%- elsif L == 'en' -%}{%- assign seminars_url = '/en/seminars/' -%} {%- elsif L == 'ja' -%}{%- assign seminars_url = '/ja/seminars/' -%} {%- else -%}{%- assign seminars_url = '/seminarios/' -%}{%- endif -%} {%- assign today = site.time | date: '%Y-%m-%d' -%} {%- assign this_month = site.time | date: '%Y-%m' -%} {%- comment -%} Week start, taken from the same key the timetable uses so the two pages never disagree about where a week begins. It shifts both the column headings and the number of blank cells before the 1st. {%- endcomment -%} {%- if S.week_start[L] == 'sun' -%} {%- assign week_days = 'sun,mon,tue,wed,thu,fri,sat' | split: ',' -%} {%- assign dow_shift = 0 -%} {%- else -%} {%- assign week_days = 'mon,tue,wed,thu,fri,sat,sun' | split: ',' -%} {%- assign dow_shift = 6 -%} {%- endif -%} {%- comment -%} Distinct months, in order, plus the month the site was built in. {%- endcomment -%} {%- comment -%} Every month from the first entry to the last, gaps included, plus the month the site was built in if it falls outside that span.
