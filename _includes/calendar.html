{%- comment -%} Dated calendar: seminars, exams, closures and changes to the regular week. Rendered at build time from _data/calendar.yml, like the weekly timetable — static HTML, indexable, no library, no fetch. Two views over one set of entries. The month grid is the default because courses here are published one to three months out, so a month usually has something in it; the list is better on a phone and better for scanning what is next. Both are in the markup and the toggle only changes which is shown, so a crawler and a reader with no JavaScript get everything either way. Every month that has entries is rendered, past ones included — the archive of who taught and when is worth keeping and worth indexing. Navigation moves between the rendered months rather than generating empty ones. Date arithmetic in Liquid, which has no date maths to speak of, is done through Unix timestamps: the first of the next month minus a day is the last day of this one. Weekday indices come from strftime %w, shifted so the week starts on Monday like the rest of the site. {%- endcomment -%} {%- assign C = site.data.calendar -%} {%- assign S = site.data.schedule -%} {%- assign L = page.lang | default: 'es' -%} {%- assign entries = C.entries | sort: 'date' -%} {%- assign today = site.time | date: '%Y-%m-%d' -%} {%- assign this_month = site.time | date: '%Y-%m' -%} {%- comment -%} Distinct months, in order, plus the month the site was built in. {%- endcomment -%} {%- assign month_keys = '' -%} {%- for e in entries -%} {%- assign ym = e.date | date: '%Y-%m' -%} {%- unless month_keys contains ym -%} {%- assign month_keys = month_keys | append: ym | append: ' ' -%} {%- endunless -%} {%- endfor -%} {%- unless month_keys contains this_month -%} {%- assign month_keys = month_keys | append: this_month | append: ' ' -%} {%- endunless -%} {%- assign months = month_keys | split: ' ' | sort -%}
